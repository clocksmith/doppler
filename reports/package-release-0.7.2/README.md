# Doppler 0.7.2 release evidence

This release adds layer projection and fixes a projection request-snapshot race.
The comparison campaign covers Qwen 3.5 0.8B, Qwen 3.5 2B, and Jupiter's
`qwen3-8-27b-text-q4k-ehaf16`. It does **not** establish that Doppler is faster
than every comparator. Flash-Next's separate 2,187-token full-logit gate remains
failing and unqualified. No tolerance was relaxed.

## Package and projection

`package-audit.json` compares the exact archive with published 0.7.1. It records
every added, removed and changed file and the final integrity. The final archive
has the same `src/` bytes as the archive used for physical qualification;
`packed-runtime-equivalence.json` records that comparison. Final differences are
package metadata and release notes, not an untested runtime change.

`browser-projection.json` records four prompts and 64 generated tokens per model
on Apple M3: Gemma 270M, Qwen 0.8B and the separately approved Gemma 1B manifest
repair. Every final-layer projection selected the recorded token. Maximum
probability differences were 1.8e-6, 1.4e-6 and 3.5e-6 respectively. The check
requires a difference no greater than 1e-5. Intermediate projections remain
labelled projected, not generated or causal.

One token's complete layer stack reads back 18–26 MiB of vocabulary logits.
Measured projection calls took 204–861 ms across these models on this busy Mac.
The buffer-pool observations are runtime-owned allocations, not physical GPU
memory. Sampling at 1 ms can miss brief peaks; the lifetime peak is also retained.
This is an installed-package API check, not Observatory deployment qualification.
The local Explore shell requested an absent `index-browser.js`; the check itself
explicitly imported the packed `src/index.js` and exercised that runtime.

`check-projection.js` retains the physical check adapted from Hatch's
`doppler-observatory/scripts/check-projection.js`. Run from this repository with
`DOPPLER_PREVIEW_ROOT` pointing at an extracted archive. The Gemma repair needs
`GEMMA_CANDIDATE` pointing at its authenticated manifest, tokenizer and shards.
Its publication and catalog promotion are deferred by the user; see
[`../gemma1b-manifest-repair-20261111/`](../gemma1b-manifest-repair-20261111/).

The snapshot regression changes the caller's vectors and removes a row while a
projection is waiting. It failed before the fix and passes afterward. The
physical projection-kernel check separately verifies multiple rows, output
projection and resource ownership on M3.

## Comparators and workload

All timings retain one warmup and three timed requests, greedy sampling,
64 generated tokens, empty context at request start, and complete request time
separate from loading. `summary.json` is generated by `node
reports/package-release-0.7.2/summarize.js`; it uses the arithmetic mean of all
timed samples, with no outlier removal. Raw receipts retain other statistics.

Small-model browser comparisons use Transformers.js **4.3.2**, its actual
ONNX Runtime WebGPU **1.31.0-dev.20260914-8d85527a0**, and Chromium 145 on Apple M3.
This is Transformers.js running ONNX inference, not two independent engines.
The 27B runner uses direct ONNX Runtime WebGPU with CPU inference fallback
disabled, Chrome 146 on Jupiter's AMD Strix Halo, and Transformers.js 4.3.0 for
tokenization only. Its upstream source is
[`aaa56b8c5accd10456819e18d3e27175afad69fc`](https://github.com/RuurdKuiper/qwen38-27b-onnx-webgpu/tree/aaa56b8c5accd10456819e18d3e27175afad69fc).

llama.cpp is source commit
[`cd959bae99ff4bed22bef2604f45241c09bbb8c8`](https://github.com/ggml-org/llama.cpp/tree/cd959bae99ff4bed22bef2604f45241c09bbb8c8),
Metal on Mac and Vulkan on Jupiter, all layers offloaded, flash attention on,
one slot, FP16 K/V and prompt caching disabled. Native complete time includes
localhost HTTP transport. Its decode statistic is server-side; streamed first
token and complete time are also retained. GGUF identities and verified LFS
SHA-256 values are in `benchmarks/*GGUF-identity.json`.

RDRR Q4_K, ONNX q4f16/INT4 and GGUF Q4_K_M/UD-Q4_K_M are different quantized
artifacts. Matching token IDs on a prompt establishes that prompt's output
agreement, not equality of weights, numerical accuracy or general model quality.
The 27B RDRR and ONNX artifacts name the same source checkpoint revision
`1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`. The retained RDRR manifest hashes to
`e29626a8d3c41c0af8c0dd945d028464dcebfef2413ba85e4f5e8695d5910d06`.

## Findings and limits

- **0.8B synthetic prompt:** all 64 output IDs match across Doppler,
  Transformers.js and llama.cpp. Browser complete-request means were 1.279 s
  for Doppler and 1.237 s for Transformers.js. The less variable native repeat
  was 0.784 s. The earlier noisy native run is retained, not silently discarded.
- **2B synthetic prompt:** all 64 output IDs match. The initial browser run
  suggested a large advantage but did not reproduce: the repeat was 1.827 s
  for Doppler and 1.889 s for Transformers.js; native was 1.379 s. Doppler's
  throughput mode recovered from 6.364 s to 1.762 s without a runtime change.
  Changing host conditions prevent a general multiplier claim.
- **Ordinary question:** both small-model ONNX outputs differ from Doppler even
  with shared pre-rendered input. The comparison gate rejects these as
  `output-parity-mismatch`. The additional native runs also differ from Doppler
  on this question. Their timings are diagnostic only; this campaign does not
  establish which quantized answer is numerically closer to the source model.
  The 64-token cap
  truncates a requested eighty-word explanation; these are fixed-work tests,
  not successful instruction-following or complete-answer evaluations.
- **27B on Jupiter:** identical 36-token input, 64-token output budget.
  Doppler Node/WebGPU averaged 8.393 s, direct browser ONNX 8.328 s, native Vulkan
  5.393 s. Doppler matches all 64 native token IDs; ONNX first differs at index
  four. No ONNX-versus-Doppler winner is qualified. Browser/Node differences,
  quantization and context allocation strategies remain explicit boundaries.

The Mac was in normal use. Disk pressure and host load changed during the
campaign. Only campaign-owned downloads and its localhost browser cache were
removed. No runtime/kernel optimization is attributed to the improved repeat.
The apparent slow throughput path was not reproducible, so no speculative
kernel change was retained. Jupiter's two protected processes stayed running;
the private test processes were sequential. Its public provider was not
restarted or reconfigured. This is not an uncontended-host qualification.

## Reproduction and retained failures

The synthetic browser command is:

```sh
node tools/compare-engines.js --model-id qwen-3-5-2b-q4k-ehaf16 \
  --doppler-surface browser --mode compute --load-mode http \
  --prefill-tokens 64 --max-tokens 64 --temperature 0 --top-k 1 --top-p 1 \
  --warmup 1 --runs 3 --warm-engine-order transformersjs-first \
  --decode-profile parity --tjs-dtype q4f16 --resource-telemetry on \
  --save --save-dir reports/package-release-0.7.2/benchmarks --skip-matrix-update --json
```

Replace the model ID for 0.8B. Natural-question argument arrays are retained in
`benchmarks/0-8b-natural-command.json` and `2b-natural-command.json`. They use one
rendered prompt and disable further chat templating. The private profile paths
and ports can be relocated. `native-request.js` consumes a comparison or the
27B contract, asserts exact input IDs and requested output count, and retains
all output IDs. `doppler-node-request.js` consumes the same 27B contract and a
frozen package. `onnx27-browser.js` runs from the pinned upstream example checkout
after its SHA-256-verified model download and local Vite server startup.

Retained failures and superseded attempts:

- An initial Transformers.js 4.2.0 offline-cache preparation failed under disk
  pressure. It has no accepted timing row; the campaign uses 4.3.2.
- `145200` and `145329` comparison receipts use independently rendered chat
  prompts; the fairness gate rejects `prompt-rendering-not-shared`. The latter
  overlapped the start of a replacement run. It is not used for a speed claim.
  Both overlapping test trees were stopped, then the shared-prompt runs were
  launched sequentially. Their receipts are `145437` and `145659`.
- The first native 27B build accidentally stamped the enclosing repository's
  revision because its source came from a tar archive. The pinned source was
  then made an independent Git checkout, verified clean, rebuilt, and rerun.
  `qwen27-llamacpp-vulkan-initial.json` remains diagnostic; the final receipt and
  `jupiter-environment.json` identify the corrected binary.
- Early native small-model receipts compared text with an unavailable harness
  field. Their `exactTextMatch: false` is not a model mismatch; the complete
  token-ID comparisons are valid. The retained runner now uses the recorded
  Doppler token IDs as its reference and asserts prompt identity too.
- Vendor registry validation finds a pre-existing Gemma 1B local-manifest digest
  mismatch: expected `734f8d…`, actual `733a27…`. The actual hash is identical
  at the starting HEAD. It was not weakened or relabelled as passing. The two
  focused comparator contract test files pass.

Next performance work needs stable paired measurements of prefill, command
recording and GPU completion waits, plus additional prompts and longer contexts.
The retained aggregate map waits include GPU completion; they do not prove
transfer overhead or identify a kernel to change. The short comparison campaign
does not close Flash-Next's numerical gate, Bee's qualification, or phone support.

## Handoff

All six final package checks pass: public boundaries, runtime closure, package
closure, 28 release claims, package kernel digests, and the installed-package
smoke. Focused projection, inspection, operation, migration and comparator
contracts pass, as do source types, architecture and style. These are scoped
checks, not a claim that the full repository suite passes. Logs are in `checks/`.

- Component: `doppler.client.model-host`, `doppler.benchmarks`, package release.
- Intent: preserved.
- Acceptance evidence: projection regression, physical projection checks,
  `browser-projection.json`, comparison receipts, package audit and release checks.
- Boundary effects: immutable projection request shape; development comparator
  upgraded to Transformers.js 4.3.2; local Qwen manifests synchronized to their
  existing approved catalog pins. No hosted model promotion, Observatory deploy,
  public-provider changes, or Flash-Next qualification.
