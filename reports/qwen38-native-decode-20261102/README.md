# Native 27B decode checkpoint

Component: `doppler.runtime-source.gpu.kernels`, `doppler.runtime-source.formats`, `doppler.runtime-source.inference.pipelines.text`.
Intent: preserved. Boundary effects: registered projection variants, shard metadata normalization, valid whole-token capture windows.

The Q5_K GEMV implementation reuses block scales, packed group metadata and high bits while preserving each lane's F32 accumulation and the baseline reduction order. The baseline entry remains available. Immediate/recorded cases, offsets, partial tiles, failure guards and independent real-weight fixtures pass on [AMD](operator-amd.json) and [M3 Metal](operator-metal.json). A full 5120-by-6144 source projection is bit-identical; timestamped component medians improve from 0.340 to 0.098 ms on [AMD](projection-amd.json), and 1.745 to 0.631 ms on [M3 Node/Metal](projection-metal.json). These component measurements are not model throughput.

In [Jupiter Chrome tuning](model-amd-screen.json), two measured 128-token short requests improve from 12.992/13.011 seconds to 11.154/11.250 seconds. All output tokens match. The separate long-input numerical observation compares 2,234,880 logits at nine positions after 2,287 input tokens: [every F32 bit and all 128 greedy tokens match](exact-long-regression.json). This is a within-Doppler regression check. The observer configuration is separate from whole-token replay timing.

[M3 whole-model screens](model-metal-screen.json) have large timing variation and establish no whole-model improvement. The [native Pooled control](native-metal-control.json) remains faster on its measured warm requests. Logical allocated GPU buffer bytes are recorded separately and do not establish physical VRAM or energy use. Wider Q4 row groups pass bitwise component checks, including [Chrome](row-group-chrome.json); model-level selection remains unqualified.

Opening screens fall from approximately 142 to 70 to 49 seconds on Jupiter by explicitly enabling the existing serialized 64 MiB verification workspace, then a bounded 64 MiB HTTP range cache. Source SHA256 verification remains enabled. These are sequential tuning observations, not a statistical opening-time comparison. The [fresh manifest derivative](manifest-identity.json) reuses identical shard files. Parsing now preserves the declared digest algorithm instead of serializing a generic SHA256 digest as a BLAKE3 alias. Earlier frozen manifests remain unchanged.

A physical lookup run exposed [nonconsecutive capture positions](replay-gap-contract.json). The replay compiler requires consecutive initial observations to identify dynamic words. Capture now retains a consecutive suffix; its compiler and numerical checks are unchanged. The focused regression fails before the fix and passes after it, and the physical lookup request completes with identical output. Lookup accepts zero of sixteen proposed tokens on this job and remains disabled in the performance configuration.

The [independent F64 diagnostic](independent-reference-gap.json) still exceeds absolute 0.001 at three sampled positions. The [final-stage decomposition](final-stage-attribution.json) locates the discrepancy upstream of the output head: the head differs by only a few millionths when given the same input. No tolerance has changed, and neither this source checkpoint nor its component tests qualify the complete model, matched-quality service, every runtime, or a Pooled advantage.

[Development checks](development-checks.json), [source identities](source-identities.json), and [retained evidence hashes](retained-files.json) bind this checkpoint.
