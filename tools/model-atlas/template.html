How to read the numbers. A "value" is one number. Weights are the model's learned numbers, loaded once. Per-token buffers are rebuilt for every token. The KV cache and linear-attention state persist across a conversation; Doppler allocates the whole KV cache when the model loads. KV sizes use the manifest's token cap, or the runtime default of 4,096 when the manifest sets none (a runtime profile can change it). Status labels come from models/catalog.json: "verified" means the catalog lists a passing test suite for that lane, not that this page ran it.

1 · Number formats

Each format stores a weight in fewer or more bits. Block formats group weights and share a scale per block, which is why their bits per weight are slightly above the nominal number. Doppler either keeps a block format packed and decodes it inside the kernel, or expands it to F16/F32 when the model loads.

2 · Paths from weights to the GPU

Every path ends in the same loader (loader/doppler-loader.js). They differ in what file they start from and what checks happen on the way.

A · Converted RDRR

Doppler's own format: manifest.json plus 64 MiB shard_NNNNN.bin files.

  1. Node-only convert reads SafeTensors, a GGUF file or a diffusers directory.
  2. Each tensor's target format comes from its role: embeddings, head, vision, or everything else. Norms, routers, biases and tensors under 1,024 values are never quantized.
  3. Shards are hashed (SHA-256 by default), with per-tensor Merkle roots over 1 MiB blocks.
  4. The manifest records formats, architecture, the execution graph (kernels with digests) and session settings.

converter/core.js:398-840 · tensor-transform.js:404-693

B · GGUF passthrough

An RDRR manifest whose shards hold the GGUF's quantized blocks byte for byte (preserveSourceTensors: true).

  1. Allowed blocks: Q4_0, Q4_1, Q5_0, Q8_0, Q5_K, Q6_K, plus F16/BF16/F32.
  2. No re-quantization; other GGUF formats cannot become Q4_K.
  3. Kernels matmul_q4_0* and matmul_q5k decode the blocks on the fly.

Used by Qwen 3.6 35B-A3B; a Qwen 3.8 27B config exists too.

tensor-transform.js:418-429 · qwen3/qwen-3-6-35b-a3b-q4_0-passthrough.json

C · Direct source (no conversion)

Node only. Reads SafeTensors, GGUF, TFLite or LiteRT files where they sit, through a synthetic manifest whose "shards" are byte ranges in the original files.

  1. Every source file is hashed in full first.
  2. Memory check: resident memory plus the largest tensor must fit the budget (default half of RAM minus 2 GiB).
  3. Allowed: F32, F16, BF16, Q4_0, Q4_1, Q5_0, Q8_0, Q4_K, Q5_K, Q6_K. Anything else: "Convert to RDRR first".
  4. TFLite INT8/INT4 tensors are expanded on the CPU at load.

tooling/node-source-runtime.js:625-788 · source-artifact-adapter.js:28-40

D · weightsRef variant

A second manifest that borrows another lane's shards and changes only runtime settings, such as F16 activations. Loading checks the target manifest's SHA-256 digest, weight-capsule ID and shard-set hash.

Used by Qwen 3.6 27B eaf16 (borrows ehaf16) and Gemma 4 E2B af16-int4ple (borrows af32-int4ple).

client/runtime/model-source.js:91-191

E · Signed Capsule

The Rig/Run lane: an Ed25519-signed bundle of manifest, shards, tokenizer, configs, evidence and WGSL sources. doppler.openCapsule checks that every shard is inside the signed set with a matching SHA-256 and size, and binds the Capsule's own shaders. Caller load options are refused; the signed plan decides.

client/model-host/index.js:389-475 · config/capsule-v3.js

F · Partitioned layers

One model split into stages by layer range (two groups by default, or N ordered stages). Each stage loads only its layers, plus the embedding (first) or head (last). Stages pass [1, T, hidden] activation frames.

Refused for MoE, shared KV, per-layer inputs, mixed KV geometry, conv layers, multimodal input and replay-prefill. Partitions run only through Capsule or pinned-manifest factories.

inference/pipelines/text/partition-execution.js:17-55 · config/layer-partition-plan.js

Packed or expanded at load

For each tensor the loader asks which kernels in the model's graph read it. If every reader is a fused Q4_K kernel, the tensor stays packed (4.5 bits). If every reader is an F16 kernel, it is expanded to F16 at load (16 bits, about 3.6 times the file size). If both read it, both copies are kept. Gemma 3 270M Q4_K, TranslateGemma, EmbeddingGemma and LFM2 have no fused Q4_K kernel in their graphs, so they expand. The Qwen and Gemma 4 Q4_K lanes keep weights packed.

loader/weight-representation-plan.js:10-146 · rules/loader/tensor-loader.rules.json

3 · Pipelines

Each pipeline below uses the same template: how a manifest reaches it, which models use it, its stages in order with the code that runs them, the buffers it allocates, and its status and limits. Shapes use T = tokens in the pass, H = hidden width, I = FFN width, V = vocabulary, nH/nKV = query/KV heads, D = head width, E/k = experts / experts per token.

3.1 Text generation

Routing
modelType transformer or gemma4 → InferencePipeline (pipelines/text.js:13-14). Unknown types lazy-load per rules/inference/config.rules.json, else fail.
Models
All Gemma 3/4, TranslateGemma, Qwen 3.5/3.6/3.8, Flash-Next, LFM2, MiniCPM, Muse Glimmer, and the GLM-OCR decoder
  1. Load in a fixed order. Compile the manifest's execution graph and apply device capability rules (for example, widen to F32 without shader-f16) → read model config from the manifest only → resolve kernels and check dtypes → tokenizer → check manifest compute dtype equals session → allocate KV cache → build the execution plan (plus an F32 fallback plan for F16 lanes) → load weights → fuse Q/K/V projections → RoPE tables → decode buffers. text/lifecycle.js:105-440
  2. Tokenize and template. Chat templates: gemma, gemma4, qwen (optional thinking prefix), chatml, llama3, gpt-oss, translategemma, glmocr. Every token ID is range-checked against V before the GPU sees it. text/init-chat-templates.js:53-72 · generator-runtime.js:78-119
  3. Embed. Gather [T, H] from the embedding table (F16, BF16, GGUF blocks or INT4), scale by √H or an explicit number, optional weightless RMSNorm. Image or audio features are spliced in here for multimodal prompts. text/embed.js:183-458
  4. Run each layer. The mixer depends on the layer type:
    • Full or sliding attention: Q [T, nH·D], K and V [T, nKV·D]; optional per-head Q/K RMSNorm; RoPE (a local table for sliding layers); write K and V to the cache; attention over the cache (contiguous, tiered, quantized or indexed); optional sigmoid output gate; output projection [T, H] plus residual.
    • Linear attention (Qwen 3.5/3.6/3.8): project qkv [T, conv width], z, a, b; causal 4-tap convolution; gated-delta recurrence that updates a fixed per-layer state; gated norm; output projection. No KV cache.
    • Short convolution (LFM2): in-projection → conv with persistent state → out-projection.
    • Indexed attention (Flash-Next): an indexer selects KV rows, and attention runs only over them, inside hyper-connection layers.
    Then the FFN: dense act(gate) × up → down through [T, I], or mixture of experts (router [T, E] → top k → experts, plus a Qwen shared expert, or a Gemma dense branch summed with the experts). Gemma 4 E2B adds a per-layer-input block. F16 lanes record a finiteness check per layer. text/layer.js:162-787 · linear-attention.js · ffn/ · moe-gpu.js
  5. Produce logits. Final norm → LM head (often the embedding table, "tied") → softcap → F32 logits [V]. Prefill computes only the last position. Rerank and choice scoring compute just the token IDs they need. text/logits/index.js:165-688
  6. Prefill. The whole prompt in one recorded pass, cut into chunks if prefillTokenChunkSize is set and submitted every 4 or 8 layers to bound buffer lifetime. text/generator/prefill-runtime.js:131-894
  7. Decode. Batched GPU decode records batchSize tokens per command buffer (embed → layers → head → penalty → sample, all on the GPU) and reads tokens back every readbackInterval batches. Otherwise single-token decode with a fused LM-head argmax/sample reads back 4 bytes per token. A "whole-token program" can record one step and replay it with only the position changing. text/generator-steps.js:357-760 · generator/decode.js · whole-token-lane.js
  8. Sample and stop. Repetition and presence penalty, temperature, top-k, top-p with a per-token seed (temperature 0 = argmax). Optional prompt-lookup speculation (greedy, verified, rolled back on rejection). Stop on EOS IDs, stop sequences, the token limit or abort. inference/token-sampling.js:285-334 · generator/speculative-runtime.js

Status and limits

  • Fails closed on Mamba and RWKV layers, CPU MoE, CPU logits, tiered or quantized KV at F32, paged KV with full-attention layers, and a manifest/session compute mismatch.
  • Draft-model and Medusa speculation are not implemented. "Self" speculation runs extra decode steps that are recorded as accepted without a verification pass.
  • Models with mixed head geometry but no explicit layer types fall back to "replay prefill", which re-runs the whole prompt every token.

3.3 Embedding

Routing
modelType embedding → EmbeddingPipeline, which only blocks generate(). Every text pipeline also exposes embed().
Models
EmbeddingGemma 300M, Qwen3 Embedding 0.6B; the protein/DNA encoders through the sequence path
  1. Tokenize without a chat template. EmbeddingGemma's task prefixes (for example task: search result | query:) are added by tooling, not the pipeline.
  2. Prefill to hidden states [T, H]; no logits. State is reset before and after. text/execution.js:264-283
  3. Final norm over all T rows.
  4. Pool to [H]: mean or last; the manifest's choice wins. gpu/kernels/embedding-pool.js
  5. Postprocess. Optional dense projections (identity activation), then L2 normalize; read back H × 4 bytes. text/embedding-extraction.js:59-230

Status and limits

  • Both embedding models are verified.
  • The KV cache is allocated at load and serves as the attention store for the single pass, sized for the full token cap. With skipEmbeddingKVCacheWrites, attention reads the current tensors and the cache goes unused.
  • embedBatch is a sequential loop. CPU extraction throws.

3.4 Sequence encoding (protein and DNA)

Routing
modelType embedding plus inference.supportsSequence and an inference.sequence block → encodeSequence
Models
AMPLIFY 120M, ESM-2 35M, ESM C 300M, Nucleotide Transformer v2 50M
  1. Tokenize with the manifest's alphabet (amino acid or nucleotide).
  2. One bidirectional pass (causal: false) to hidden states [T, H].
  3. Final norm (LayerNorm for ESM and NT, RMSNorm for AMPLIFY).
  4. Per-token embeddings [T, H].
  5. Mean pool excluding special token IDs; throws if every token is excluded.
  6. Per-position logits [T, V], AMPLIFY only. Masked-token prediction is this single pass, with no iterative fill-in loop. text/execution.js:290-337 · embedding-extraction.js:14-33

Status and limits

  • All four are verified and published on Hugging Face; none is stored on mac-host.
  • All four set skipEmbeddingKVCacheWrites. Since a76f1add the loader skips KV allocation for these encoders; text embedders and rerankers retain their caches.

3.5 Rerank

Routing
inference.supportsRerank plus an inference.rerank block of format qwen3_yes_no_logit. Run by inference/rerank.js and the tooling harness, not a pipeline method.
Models
Qwen3 Reranker 0.6B (F16 and Q4_K lanes)
  1. Build the prompt: prefix + template(instruction, query, document) + suffix, never the chat template. inference/rerank.js:20-80
  2. Share the common prefix: the harness prefills the tokens shared by all documents once, then rewinds to that point before each document. tooling/browser-harness/text-execution.js:70-154
  3. Prefill each suffix and compute logits for only the "yes" and "no" token IDs. text/logits/index.js:586-623
  4. Score = yes − no (or the yes logit alone); probability = sigmoid(score).

Status and limits

  • Both lanes verified. The client scoped session has no rerank method; use tooling or a program bundle.

3.6 Image → text

Routing
Enabled when the manifest has image_token_id and quantizationInfo.vision. Encoder chosen by vision_config.vision_architecture: gemma4, glmocr or qwen3vl. Entry points: transcribeImage (gemma4, glmocr) and embedImage (all three).
Models
Gemma 4 E2B, GLM-OCR, Qwen 3.5 0.8B (embedImage only)
  1. Preprocess on the CPU.
    • Gemma 4: bicubic resize to a soft-token budget (70, 140, 280, 560 or 1,120), 16-pixel patches → [N, 768].
    • GLM-OCR: PIL-style bicubic, 14-pixel patches repeated over 2 frames → [N, 1,176].
    • Qwen3-VL: bilinear resize to about one megapixel.
    vision/gemma4.js:135-227 · glmocr-preprocess.js · image-preprocess.js
  2. Patch embed (linear plus position embedding) → [N, h].
  3. Encoder layers.
    • Gemma 4: 16 layers, 12 heads × 64, 2-D RoPE, GELU MLP.
    • GLM-OCR: depth from config, 2-D RoPE, SiLU MLP with biases.
    • Qwen3-VL: ViT blocks.
  4. Reduce tokens.
    • Gemma 4: 3×3 average pool → N/9 tokens, then project to text width 1,536.
    • GLM-OCR: 2×2 spatial merge → N/4 tokens, downsample, then the merger MLP to text width.
  5. Splice into the prompt. Expand the image placeholder to N tokens and override their embeddings with the features. Gemma marks the image span bidirectional. GLM-OCR swaps in 3-axis rotary positions for the run. text/image-transcription.js:102-303 · vision/glmocr-rope.js
  6. Decode greedily (temperature 0, top-k 1) through text generation.

Buffers

Gemma 4 E2B (16 layers, 12 query and 12 KV heads × 64): patches [≤2,520, 768] → hidden [N, 768] → Q, K, V [N, 768] each → MLP [N, 3,072] → pooled [≤280, 768] → output [≤280, 1,536], all F32. GLM-OCR: patches [N, 1,176] → hidden [N, 1,024] → QKV [N, 3,072] → merge [N/4, 4,096] → output [N/4, 1,536].

Status and limits

  • Gemma 4 and GLM-OCR are implemented. Qwen3-VL is partial: no position encoding in its encoder, and a loaded merger LayerNorm is unused (reported by the trace, not re-checked).
  • The catalog's E2B "verified" covers the text inference suite; no separate vision receipt was found.

3.7 Audio → text

Routing
Enabled when the manifest has audio_token_id and quantizationInfo.audio. Only gemma4 audio; the encoder lives in src/experimental/audio/.
Models
Gemma 4 E2B (manifest flags on)
  1. Mel features on the CPU: 16 kHz, 512-point FFT, hop 160, window 400, 80 mel bins → [frames, 80]. These parameters are fixed in code; the manifest does not change them. pipelines/audio/mel.js
  2. Subsample: two stride-2 3×3 convolutions with RMSNorm, then a linear to [seq, 1,024].
  3. Conformer layers (12): macaron FFN, chunked self-attention (left 13, chunk 12), 1-D conv module.
  4. Project to [seq, 1,536].
  5. Splice and decode greedily, as for images.

Status and limits

  • repaired, not qualified Since a76f1add, upload receives an owned GPU buffer and subsampling keeps its declared layout. Previously stage 2 called uploadData(melFeatures, 'audio_mel_input') (experimental/audio/gemma4.js:27), but uploadData takes a GPU buffer first (memory/buffer-pool.js:838). That historical call threw before GPU work. Focused tests cover the repair; a full audio-model reference run is still required.

3.8 Video → text

Routing
Same gate as image → text; transcribeVideo
Models
Gemma 4 E2B
  1. Sample frames: up to 8, evenly spaced.
  2. Encode each frame with the image encoder and a per-frame token budget. There is no temporal modeling.
  3. Concatenate the frame features into one buffer.
  4. Splice and decode greedily under <|video|> delimiters.

Status and limits

  • fixed, not run The concatenation used to size rows with outHiddenSize ?? hiddenSize, so E2B frames were copied at 768 values while the features are 1,536 wide. Since 3a58230f each encoder returns featureSize, the planner requires every frame to agree, and transcribeVideo checks it against the text hidden size. A unit test covers the plan; no GPU video run has been done.
  • The single-frame NaN index is fixed in the same commit.

3.9 Diffusion text (DiffusionGemma)

Routing
modelType diffusion_gemma → lazy-loaded pipelines/diffusion-gemma/pipeline.js, which drives an internal text pipeline
Models
DiffusionGemma 26B-A4B
  1. Prefill the prompt into the KV cache only (prefillKVOnly).
  2. Start a canvas of 256 tokens drawn uniformly from the 262,144-token vocabulary.
  3. Denoise for up to 48 steps, with temperature moving from 0.8 toward 0.4.
    • Self-conditioning blends the previous step's soft predictions into the embeddings.
    • A non-causal pass runs over [prompt KV + canvas].
    • Logits [256, 262,144] are reduced on the GPU to an argmax and an entropy per position; only 8 bytes per position are read back.
    text/generator/diffusion.js:453-600
  4. Accept confident positions: lowest entropy first while the running total stays under the entropy bound (0.1); re-randomize the rest; stop early when everything is stable and mean entropy is under 0.005. diffusion-gemma/sampling.js:169-244
  5. Emit the canvas (padding dropped, stop at EOS), append it to the KV cache, start the next canvas.

Buffers

Logits 256 × 262,144 × 4 bytes = 256 MiB per step; decoder K/V per layer [prompt + 256, nKV × D]; argmax and entropy [256] each.

Status and limits

  • Experimental; the catalog lists no test. The GPU path accepts argmax tokens while the CPU-logits path accepts sampled tokens, so the two do not match exactly.

3.10 Image generation

Routing
modelType diffusion → experimental/diffusion/pipeline.js. Runtime layouts allowed: sd3, flux.
Models
None runnable. Sana Sprint 0.6B (layout sana) is rejected at load.
  1. Tokenize for CLIP-L, CLIP-G and T5 (77 tokens for CLIP).
  2. Encode text. Pooled CLIP vectors, plus T5 hidden states as context; the CLIP hidden states are dropped.
  3. Draw seeded Gaussian latents [channels, H/scale, W/scale].
  4. Denoise for N steps (default 20).
    • Patchify, then joint attention over image and text tokens with adaLN modulation.
    • Classifier-free guidance runs a second pass on the negative prompt.
    • Flow-match Euler or SCM scheduler step.
  5. Decode with the VAE in F16 (standard VAE or DC-AE).
  6. Convert to RGBA pixels.

Status and limits

  • Experimental. flux loads but always runs the SD3 transformer and needs T5, so it cannot run.
  • Schedulers other than flow-match Euler and SCM resolve but throw at the first step.
  • The trace also reports an inverted flow-match shift and a final step that does nothing. Neither was re-checked.

3.11 Registered pipelines with no model

Structured JSON head

Eleven structured_json_head / dream_* modelTypes. Runs text generation, then parses JSON from the output (raw, fenced, or first { to last }) and hashes the prompt. The JSON and TSV grammar masks are opt-in logit masks on CPU logits.

Energy

A toy energy-minimization demo with no weights: random state and target vectors, gradient steps until energy ≤ 1e-4, or a 5×5 "Quintel" grid puzzle with Adam on the GPU.

Energy row head

Seven modelTypes. Weights are inline JSON arrays. Each row's features are relaxed toward the weights for 3 steps, then scored as logit = w·s + b − energy, passed through a sigmoid and sorted.
